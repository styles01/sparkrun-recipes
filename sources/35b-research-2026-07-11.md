## Key Findings

### 1. Model Choice: Stay on nvidia/Qwen3.6-35B-A3B-NVFP4

Unsloth Fast is 15% slower on GB10:
- NVIDIA NVFP4: 103 tok/s avg (coding: 112, reasoning: 93, agentic: 101)
- Unsloth Fast: 88 tok/s avg (coding: 96, reasoning: 77, agentic: 85)
- Unsloth W4A4 advantage only shows on B200, not GB10

### 2. MTP k=3 Does NOT Collapse on Prose (but k=2 might be better)

Acceptance rates per position (from shahizat's benchmark report):

| Workload | P0 | P1 | P2 | Avg |
|---|---|---|---|---|
| Prompt-heavy (8K/1K) | 80.2% | 68.0% | 58.3% | 68.8% |
| Decode-heavy (1K/8K) | 91.8% | 80.4% | 68.9% | 80.4% |
| Balanced (1K/1K) | 84.9% | 71.9% | 58.3% | 71.7% |

Unsloth recommends k=2: "acceptance drops precipitously from 83% to 50% with 4 draft tokens"

### 4. AEON Bench Recipe (Attested Benchmark Run)

```bash
docker run --rm --gpus all --name replica \
  -v ./weights:/model -v ./drafter:/drafter -p 8000:8000 \
  --entrypoint vllm ghcr.io/aeon-7/aeon-vllm-ultimate:latest \
  serve /model \
  --served-model-name model-under-test \
  --host 0.0.0.0 --port 8000 \
  --max-model-len 65536 --gpu-memory-utilization 0.8 \
  --quantization compressed-tensors --kv-cache-dtype fp8_e4m3 \
  --attention-backend triton_attn \
  --max-num-seqs 64 --max-num-batched-tokens 32768 \
  --enable-chunked-prefill --generation-config vllm \
  --reasoning-parser qwen3 --tool-call-parser qwen3_coder --enable-auto-tool-choice \
  --enable-prefix-caching --trust-remote-code \
  --speculative-config '{"method": "dflash", "model": "/drafter", "num_speculative_tokens": 11, "attention_backend": "TRITON_ATTN"}'
```

### 5. Production Recipe (AEON-7, stable, 256K context)

- `--attention-backend flash_attn` (not triton_attn)
- No `--kv-cache-dtype` (BF16 KV for DFlash stability)
- `--max-model-len 262144`
- `--gpu-memory-utilization 0.85`
- `--max-num-batched-tokens 16384` (not 65536 — exceeds compile range)
- DFlash n=11 (not 15 — wasted draft compute)
- `VLLM_TEST_FORCE_FP8_MARLIN=1`

### 8. FlashInfer Hang — Known Issue

- FlashInfer has no pre-compiled cubins for SM12.1 in older Docker images
- Falls back to JIT CUDA kernel compilation which deadlocks silently on SM12.1
- Fix: FlashInfer 0.6.13+ includes pre-compiled SM12.1 cubins
- Diagnostic: `python3 -c "import vllm.envs as e; print(e.VLLM_HAS_FLASHINFER_CUBIN)"`
- Workaround: `--attention-backend TRITON_ATTN` + `VLLM_USE_FLASHINFER_SAMPLER=0`
